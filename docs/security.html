Security

What the framework does for you, what it expects from you, and the switches involved.

CSRF

The global csrf middleware rejects any POST, PUT, PATCH or DELETE request that lacks the session's token, answering 419. Forms include it with {csrf_field}; JavaScript reads it from {csrf_meta} and sends the X-CSRF-TOKEN header.

<form method="post" action="{navigate name='contact.store'}">
    {csrf_field}
    ...
</form>
fetch(url, { method: 'POST', headers: { 'X-CSRF-TOKEN': document.querySelector('meta[name=csrf-token]').content } })

To exempt a pure API, run it in its own entry point or replace the global list with global_middleware([]) and protect it with tokens instead. Cookies use SameSite=Lax as a second layer.

Response headers and CSP

config/security.php controls the headers sent on every response: X-Content-Type-Options, X-Frame-Options, Referrer-Policy, Permissions-Policy and a Content-Security-Policy that allows only same-origin scripts, styles, images and fonts. That is why Bootstrap is self-hosted. Inline scripts need the per-request nonce:

<script nonce="{csp_nonce}">...</script>

Edit the directives in the config to allow additional origins. HSTS_ENABLED=true sends Strict-Transport-Security on HTTPS responses; enable it only once the site is served exclusively over TLS, because browsers remember it for a year. X-Powered-By is removed.

Sessions and cookies

  • Session cookies are HttpOnly, SameSite=Lax, and Secure on HTTPS (or always, with SESSION_SECURE_COOKIE=true).
  • PHP strict mode is on, so a session ID chosen by the client is never accepted.
  • The ID is regenerated on login, logout and remember-me login, which prevents session fixation.
  • Idle sessions expire after SESSION_LIFETIME minutes.

Passwords and login

  • Passwords are hashed with password_hash() and re-hashed on login when the algorithm defaults change.
  • An unknown email is verified against a dummy hash so a login attempt takes the same time either way.
  • Login and registration are throttled per IP (throttle:5,1); adjust in routes/web.php.
  • Remember-me cookies hold a random token; only its HMAC (keyed with APP_KEY) is stored, so a leaked database cannot forge cookies. Logging out invalidates the token.

Input and output

  • input() and request() never include cookies, unlike $_REQUEST.
  • validated() returns only the fields you declared; mass assignment is limited further by each model's $fillable.
  • Smarty escapes every {$variable}; only |raw output is unescaped.
  • Redirects from back() and auth_intended() only follow same-host URLs (url_is_local()), closing open-redirect holes.
  • request_host() rejects header-injected values.

Database

  • Every value is bound; the raw helpers take bindings only.
  • Table and column names are validated against a strict pattern, so a user-supplied sort column cannot inject SQL. Operators and directions are whitelisted.
  • A failed connection is rethrown without the original exception, whose trace would contain the password.

Secrets and files

  • Secrets live in .env, which is git-ignored and blocked by .htaccess. .env.example holds placeholders.
  • The debug page never prints function arguments from stack traces.
  • Every directory except assets/ and docs/ denies web access through its own .htaccess.
  • Uploaded files should be moved outside the web root or into a directory that never executes PHP.

Authorization

Protect actions with policies and gates rather than ad-hoc checks, and put auth before can: in route middleware. A policy method is never called for a guest unless its first parameter is nullable. See Authorization.

Checklist for production

  • APP_DEBUG=false, APP_ENV=production, a generated APP_KEY.
  • HTTPS everywhere, then HSTS_ENABLED=true.
  • storage/ writable by the web server, everything else read-only.
  • Review config/security.php if you add third-party scripts or fonts.
  • Keep PHP and MariaDB updated; the framework has no other dependencies to track.
