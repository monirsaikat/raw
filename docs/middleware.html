YYourApp Framework docs

Middleware

Named handlers that wrap an action. Each receives $next and decides whether to call it, plus any parameters written after a colon in the route.

Writing middleware

php console.php make:middleware admin      # middleware/admin.php
<?php

middleware('admin', function (callable $next) {
    abort_unless(auth_user()?->is_admin, 403);

    return $next();
});

Every file in middleware/ is loaded by bootstrap, so the handler is registered automatically. A handler returns either the result of $next() or its own response (a Response, a string, an array) to stop the request early. Throwing abort() works too.

Parameters

Text after a colon is split on commas and passed as extra arguments:

middleware('role', function (callable $next, string ...$roles) {
    abort_unless(in_array(auth_user()?->role, $roles, true), 403);

    return $next();
});

get('/reports', 'ReportController@index', 'reports', ['auth', 'role:admin,editor']);

Class-based middleware

Register a class name instead of a closure. The class is built by the container, so it can declare dependencies, and its handle() method receives $next and the parameters:

class LogRequests
{
    public function __construct(private Clock $clock)
    {
    }

    public function handle(callable $next, string $channel = 'http')
    {
        log_info('{method} {path}', ['method' => request_method(), 'path' => request_path(), 'channel' => $channel]);

        return $next();
    }
}

middleware('log', LogRequests::class);

Attaching middleware

get('/account', 'AuthController@account', 'account', ['auth']);            // one route

group(['middleware' => ['auth', 'can:admin']], function () { ... });      // every route in a group

add_global_middleware('log');                                              // every route
global_middleware(['csrf', 'log']);                                         // replace the global list

Order: the global list first, then the group's middleware, then the route's own, outermost to innermost. csrf is global by default; removing it with global_middleware([]) disables CSRF protection everywhere, so only do that for a pure API.

Built-in middleware

NameBehaviour
csrfRejects POST/PUT/PATCH/DELETE requests without a valid _token field or X-CSRF-TOKEN header with a 419. Global by default.
authRequires a logged-in user. Guests are redirected to the login route (the requested URL is remembered for auth_intended()) or get a 401 JSON payload when they ask for JSON.
guestSends logged-in users to the home route; used on login and registration pages.
throttle:max,minutesAllows max requests per client IP and route within the window, then answers 429 with Retry-After.
can:ability,arguments…Authorizes the current user; see Authorization. 403 on failure.

Order matters

A login route usually lists ['guest', 'throttle:5,1']: logged-in users are bounced home before their attempt counts. A protected page lists ['auth', 'can:update,Post@id']: guests are sent to log in before any policy runs.

Testing middleware

test('admin middleware blocks members', function () {
    get('/admin', fn () => 'ok', null, ['admin']);

    acting_as(User::factory()->create(['is_admin' => 0]));
    http_get('/admin')->assertForbidden();

    acting_as(User::factory()->create(['is_admin' => 1]));
    http_get('/admin')->assertOk();
});

Middleware can also be exercised directly: run_middleware(['role:admin'], fn () => 'core') returns whatever the chain produces.
