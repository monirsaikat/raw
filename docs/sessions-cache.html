Sessions, flash and cache

State that survives between requests: the session for one visitor, flash data for exactly one following request, a file cache for everyone, and rate limiting on top of it.

Sessions

session_set('cart', $items);       session_get('cart', []);       session_has('cart');
session_pull('once');              // get and forget
session_forget('cart');            session_all();                 session_flush();
session_regenerate();              // new ID, same data — done automatically on login and logout
session_invalidate();              // wipe data and rotate the ID

Nothing is started until the first call, so a request that never touches the session pays nothing. Settings live in config/session.php: cookie name (SESSION_NAME), idle timeout in minutes (SESSION_LIFETIME, 0 disables), path, domain, SameSite=Lax, and the Secure flag (forced by SESSION_SECURE_COOKIE, and set automatically on HTTPS). Cookies are always HttpOnly; PHP's strict mode rejects unknown session IDs.

Under the CLI (console commands, tests) $_SESSION is a plain array, so the same code runs without a web server.

Session drivers

SESSION_DRIVER chooses where session data lives. The handler is registered with session_set_save_handler() just before the session starts, so every driver keeps the lazy start, strict mode and idle timeout above.

DriverStorageWhen
file (default)PHP's native files in session.save_pathSingle server. Nothing to set up.
databaseThe sessions table: id, payload, last_activity, user_id, ip_address, user_agentSeveral web servers, or when you want to list a user's active sessions and log them out everywhere.
cookieThe serialised session, encrypted with APP_KEY, in a <name>_payload cookieStateless servers with small sessions. Browsers cap a cookie at 4 KB: the auth id, CSRF token and a flash message fit; a cart does not. A payload over the limit is logged and dropped, keeping the previous session.
arrayMemory, for the current request onlyTests and endpoints that must never persist anything.
php console.php session:table     # confirms (or creates) the sessions migration
php console.php migrate
# .env
SESSION_DRIVER=database
SESSION_TABLE=sessions            # SESSION_CONNECTION= for a dedicated connection

The database driver stores the logged-in user's id, IP and user agent next to each session and garbage-collects rows older than SESSION_LIFETIME. It implements PHP's validateId(), so strict mode keeps rejecting session IDs the server never issued. SESSION_LAZY_WRITE=true (default) skips the write when nothing in the session changed, which saves a file or database write on most requests; set it to false to keep last_activity exact on every request.

Flash data

Flash values are written for the next request and readable throughout it, which is what the post-redirect-get pattern needs:

flash('success', 'Saved.');              // visible on the next request
return redirect_route('posts.index');

flash('success');                        // on that next request: "Saved." (repeatable reads)
flash_has('success');   flash_all();
flash_now('info', 'Shown right now');    // current request only
flash_keep();                            // carry the current bag one request further (a second redirect)

Templates receive the whole bag as $flash, and views/includes/alerts.tpl renders success, error, warning and info as Bootstrap alerts. Validation uses the same mechanism for errors and old; old('email') reads flashed input.

Cache

cache_set('stats', $stats, 600);                          // seconds; 0 = forever
cache_get('stats');   cache_get('stats', $default);   cache_has('stats');
cache_forget('stats');   cache_flush();

$stats = cache_remember('stats', 600, fn () => Database::table('orders')->count());

Values are serialised into storage/cache, written through a temporary file so readers never see a half-written entry; anything serialisable can be stored, including models and collections. console cache:clear empties the directory.

Response caching

Whole GET responses can be cached per route with the cache.response:ttl middleware, which stores status, headers and body in the same file cache keyed by the full URL and answers later requests with X-Cache: HIT without running the action. It steps aside for logged-in visitors, flash messages, non-GET requests and private/no-store responses. Pair it with cache.headers for browser caching:

get('/sitemap.xml', 'SitemapController@index', 'sitemap', ['cache.response:600']);
get('/docs/{page}', 'DocsController@show', 'docs', ['cache.headers:public,max_age=3600,etag']);

response_cache_forget(url('sitemap.xml'));   // evict one entry after a change

Both middleware are documented on the Security page under HTTP caching middleware.

Rate limiting

post('/login', 'AuthController@login', 'login.store', ['throttle:5,1']);    // 5 per minute per IP
post('/api/upload', 'UploadController@store', null, ['throttle:60,60']);    // 60 per hour

The throttle middleware counts requests per client IP, method and path in the cache. When the limit is exceeded it answers 429 with a Retry-After header and an error page or JSON message. The primitives are available for other keys:

$limit = rate_limit_attempt('otp:' . $user->id, 3, 300);   // ['allowed' => bool, 'remaining' => int, 'retry_after' => seconds]
rate_limit_clear('otp:' . $user->id);
