Container

A dependency injection container with reflection-based auto-wiring. Controllers, class-based middleware and policies are built through it, so their constructor dependencies arrive automatically.

Resolving

$builder = app(ReportBuilder::class);      // constructor dependencies resolved recursively
$container = app();                        // the Container itself
app()->has(ReportBuilder::class);          // bound, or a class it could build

A class that is not bound is built by reflection: each constructor parameter typed with a class is resolved the same way; scalar parameters take their default value; anything unresolvable throws ContainerException naming the parameter.

Bindings

app()->bind(PaymentGateway::class, StripeGateway::class);                  // interface → implementation, fresh each time
app()->singleton(Mailer::class, fn (Container $app) => new Mailer(config('mail')));   // built once, then shared
app()->singleton(Clock::class);                                            // share an auto-wired class
app()->instance(Settings::class, $settings);                               // an existing object
app()->alias('mailer', Mailer::class);                                     // app('mailer')

app()->when(ReportController::class)->needs(Cache::class)->give(FileCache::class);   // contextual
app()->when(ImportJob::class)->needs(Cache::class)->give(fn () => new ArrayCache());

Closures receive the container and any parameters passed to make(). Declare bindings in config/container.php so they are registered at bootstrap:

return [
    'bindings' => ['PaymentGateway' => 'StripeGateway'],
    'singletons' => ['Mailer' => fn (Container $app) => new Mailer(config('mail'))],
    'aliases' => ['mailer' => 'Mailer'],
];

Parameters

app()->make(Report::class, ['year' => 2026]);            // by parameter name
app('greeting', ['name' => 'Ann']);                       // forwarded to a closure binding

Calling with injection

app()->call([$service, 'run'], ['limit' => 10]);        // method injection
app()->call('ReportController@show', [5]);                // Class@method, positional arguments
app()->call(fn (Mailer $mailer, string $to) => ..., ['to' => 'a@b.co']);
app()->call(ImportJob::class);                            // invokable class

For each parameter the container tries, in order: a value passed by name, a positional value that fits the type, a dependency from the container, the parameter's default, null when nullable. This is exactly how route actions receive route parameters and injected services together.

Where the container is used

  • Route actions: the controller is built with make() and the method invoked with call(). See Controllers.
  • Class-based middleware: middleware('log', LogRequests::class).
  • Policies and gate callbacks written as 'Class@method'.
  • Your own services: app(InvoiceService::class) anywhere.

Inspection and reset

app()->bound(Mailer::class);   app()->resolved(Mailer::class);   app()->forget(Mailer::class);
app()->flush();                // everything gone; container_boot() reloads config/container.php

Errors

MessageMeaning
Unresolvable parameter [$count] in Foo::__construct()A scalar without a default; pass it by name or bind the class with a closure.
[Cache] is an interface and is not instantiableBind the interface to a class in config/container.php.
Circular dependency: A -> B -> ATwo constructors require each other; inject a factory or pass one lazily.

Testing

The test runner flushes the container before every test and re-runs container_boot(), so bindings made in one test never leak into another. Replace a service under test with app()->instance(Mailer::class, new FakeMailer()).
