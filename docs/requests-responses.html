Requests and responses

Functions for reading the current request and building the response. Input never includes cookies, JSON bodies are merged in transparently, and every response is a small Response object.

Reading input

input();                       // all input, strings trimmed (GET + form body or JSON body)
input('email');                // one field, trimmed, or null
input('page', 1);              // with a default
request('email');              // untrimmed
query('page');                 // query string only
input_only(['name', 'email']);
input_except(['_token']);
has_input('remember');         // present and not blank
request_file('avatar');        // $_FILES entry, or null when nothing was uploaded
old('email');                  // the previous request's input after a failed validation

The body wins over the query string when both carry the same key. When the request's Content-Type is JSON the decoded body replaces the form fields, so an API client and a form post look identical to the action. request_json() and request_body() expose the raw body when needed.

Request facts

FunctionReturns
request_method()GET, POST, PUT, PATCH, DELETE or HEAD. A POST with a _method field reports the spoofed verb.
request_real_method()The verb actually used on the wire.
request_path()Path relative to the app root, normalised: /about.
request_uri(), request_url()Path including the base path; the full absolute URL.
request_host(), request_ip(), request_is_secure()Sanitised host, client address, whether HTTPS (or X-Forwarded-Proto: https).
request_header('X-Custom', $default)Any request header.
request_is_json(), request_is_ajax()JSON content type; X-Requested-With: XMLHttpRequest.
wants_json()The client asked for JSON (Accept) or sent JSON without accepting HTML. Error responses use this to choose JSON over HTML.

Method spoofing

HTML forms can only send GET and POST. To reach a PUT, PATCH or DELETE route, post a _method field:

<form method="post" action="{navigate name='posts.destroy' id=$post.id}">
    {csrf_field}
    {method_field method='DELETE'}
    <button>Delete</button>
</form>

Building responses

return view('posts/show', ['post' => $post]);                 // string → HTML 200
return ['ok' => true];                                       // array → JSON 200
return $post;                                                // Model/Collection/Paginator → JSON
return json(['created' => $post->id], 201);
return response('plain text', 200, ['Content-Type' => 'text/plain']);
return response('')->withStatus(204)->header('X-Reason', 'none');
return redirect('/somewhere');
return redirect_route('posts.show', ['id' => $post->id]);
return redirect_route('home', [], 301);
return back();                                               // previous page
return back('/fallback');

back() uses the Referer when it points at this host, then the last GET URL stored in the session, then the fallback. Foreign or protocol-relative URLs are never followed, which closes the open-redirect hole.

The Response object

$response = new Response('body', 200, ['X-Thing' => 'value']);
$response->header('Cache-Control', 'no-store');
$response->withHeaders(['X-A' => 1, 'X-B' => 2]);
$response->withStatus(202);
$response->status; $response->body; $response->headers;   // public properties
(string) $response;                                        // the body

Header names are normalised (content-type becomes Content-Type). send() writes the status line explicitly, so non-standard codes such as 419 and 422 survive Apache, which would otherwise rewrite unknown codes to 500.

Stopping with an error

abort(404);
abort(403, 'Not yours');
abort(503, 'Back soon', ['Retry-After' => '120']);
abort_if($post->locked, 423);
abort_unless(auth_check(), 401);

These throw an HttpException that the handler renders as views/errors/{status}.tpl, the generic errors/error.tpl, or JSON. See Errors and logging.

Content negotiation

Actions can serve both browsers and API clients:

public function index()
{
    $posts = Post::latest()->paginate(20);

    return wants_json() ? $posts : view('posts/index', ['posts' => $posts]);
}

Validation failures follow the same rule automatically: a redirect back for browsers, a 422 JSON payload for API clients.

File uploads

$file = request_file('avatar');

if ($file !== null && $file['error'] === UPLOAD_ERR_OK) {
    $name = str_random(16) . '.' . pathinfo($file['name'], PATHINFO_EXTENSION);
    move_uploaded_file($file['tmp_name'], BASE_PATH . '/storage/uploads/' . $name);
}

Keep uploads outside assets/ unless they are meant to be public, and validate the type with your own checks (mime_content_type()) before trusting the file.
