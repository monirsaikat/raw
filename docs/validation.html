Validation

One call validates input, redirects back with errors when it fails, and returns exactly the fields you asked for when it succeeds.

validated()

$data = validated(input(), [
    'name' => 'required|max:100',
    'email' => 'required|email|unique:users,email',
    'password' => 'required|min:8|confirmed',
    'website' => 'nullable|url',
], [
    'email.unique' => 'That email is already registered.',
]);

User::create([...$data, 'password' => User::hashPassword($data['password'])]);

On failure a ValidationException is thrown. The exception handler flashes the errors and the input (minus _token, _method and anything whose name contains "password") and redirects back; API clients receive a 422 JSON payload instead:

{"message": "The given data was invalid.", "errors": {"email": ["The email must be a valid email address."]}}

The returned array contains only the keys named in the rules (password_confirmation and any extra fields are dropped), so it is safe to pass to Model::create().

validate()

Returns the error array instead of throwing, for cases where you handle failure yourself:

$errors = validate($data, ['email' => 'required|email']);

if ($errors !== []) {
    return back_with_errors($errors);          // flashes errors + old input, redirects back
}

Errors are keyed by field; each value is a list of messages. Rules stop at the first failure per field, so a field has at most one message.

Rules

RulePasses when
requiredPresent and not empty (null, '' and [] are empty; '0' is not).
presentThe key exists, even if empty.
required_if:other,valueRequired when other equals one of the values.
required_with:other, required_without:otherRequired when other is (not) filled.
acceptedyes, on, 1 or true (terms checkboxes).
nullable, sometimessometimes skips every rule when the key is absent. Non-implicit rules already skip empty values, so nullable is documentation.
string, numeric, integer, boolean, arrayType checks. boolean accepts 0/1, '0'/'1', 'true'/'false'.
email, url, ip, jsonFormat checks.
date, date_format:Y-m-d, before:date, after:dateParsable date; exact format; ordering against a date or strtotime() expression.
alpha, alpha_num, alpha_dashUnicode letters; plus digits; plus dashes and underscores.
digits:4Exactly that many digits.
min:n, max:n, between:a,b, size:nLength for strings, value for numeric/integer fields, item count for arrays.
in:a,b, not_in:a,bMembership.
regex:/pattern/, not_regex:/pattern/Pattern match. Use array syntax when the pattern contains |.
starts_with:a,b, ends_with:a,bPrefix or suffix.
confirmedEquals {field}_confirmation.
same:other, different:otherCompared with another field.
unique:table,column,exceptId,idColumnNo row has the value. Column defaults to the field name; pass the id to ignore on updates.
exists:table,columnA row has the value.

Rules can be a pipe-separated string or an array; the array form is required when a rule's parameter contains |:

'time' => ['required', 'regex:/^\d{2}:\d{2}$/'],
'slug' => ['required', 'regex:/^(news|blog)-[a-z0-9-]+$/'],

Messages

The default messages use the field name with underscores turned into spaces: "The first name field is required." Override per field and rule, or per rule:

validated(input(), $rules, [
    'name.required' => 'Please tell us your name.',
    'max' => ':field is limited to :max characters.',
]);

Placeholders: :field (alias :attribute), :param (first parameter), :params, :min, :max, :other, :value.

App-wide messages, per-field overrides and field display names live in lang/<locale>/validation.php and follow the current locale; see Localization.

Custom rules

// e.g. in middleware/ or a bootstrap file of your own
validator_extend('even', fn ($value) => (int) $value % 2 === 0, 'The :field must be even.');

validator_extend('slug_available', function ($value, array $params, array $data, string $field) {
    return !Post::where('slug', $value)->exists();
}, 'That slug is taken.');

The callback receives the value, the rule's parameters, all the data, the field name and whether the field is numeric. Return true to pass.

Displaying errors in templates

$errors and $old are available in every template automatically after a redirect back:

<input type="email" name="email" value="{$old.email|default:''}"
       class="form-control{if isset($errors.email)} is-invalid{/if}">
{if isset($errors.email)}
    <div class="invalid-feedback">{$errors.email.0}</div>
{/if}

Manual validation flow

public function login()
{
    $data = validated(input(), ['email' => 'required|email', 'password' => 'required']);

    if (!auth_attempt($data['email'], $data['password'], has_input('remember'))) {
        return back_with_errors(['email' => [__('auth.failed')]]);
    }

    return auth_intended(route_url('account'));
}
