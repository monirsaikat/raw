Migrations and seeding

Schema changes are versioned files in database/migrations/, written with the schema builder or as plain SQL. Seeders and factories fill the tables.

Writing a migration

php console.php make:migration create_posts_table            # Schema::create stub
php console.php make:migration add_slug_to_posts_table       # Schema::table stub (name pattern ..._to_X_table)
php console.php make:migration anything --create=posts       # explicit
php console.php make:migration anything --table=posts
php console.php make:migration anything --sql                # SQL file instead of PHP
<?php

return new class extends Migration
{
    public function up(): void
    {
        Schema::create('posts', function (Blueprint $table) {
            $table->id();
            $table->foreignId('user_id')->constrained()->cascadeOnDelete();
            $table->string('title', 150)->unique();
            $table->string('slug')->nullable()->index();
            $table->text('body')->nullable();
            $table->enum('status', ['draft', 'live'])->default('draft');
            $table->decimal('price', 10, 2)->unsigned()->default(0);
            $table->boolean('featured')->default(false);
            $table->json('meta')->nullable();
            $table->dateTime('published_at')->nullable();
            $table->timestamps();
            $table->softDeletes();
            $table->index(['status', 'published_at']);
        });
    }

    public function down(): void
    {
        Schema::dropIfExists('posts');
    }
};

Files are named YYYY_MM_DD_HHMMSS_description.php and run in name order. Set protected ?string $connection = 'other'; on the class to target another connection.

Running migrations

CommandEffect
migrateRuns pending migrations as one batch. --seed runs the seeders afterwards.
migrate:rollbackReverts the last batch (--step=2 for more).
migrate:resetReverts everything.
migrate:freshDrops every table and migrates from scratch. Asks for confirmation; --force skips it; --seed seeds afterwards.
migrate:statusLists every file with its batch and run time.

Applied migrations are recorded in the migrations table.

id() and foreignId() are both INT UNSIGNED so foreign keys line up with the tables that already exist. Use bigIncrements() with unsignedBigInteger() if you want 64-bit keys.

Column modifiers

->nullable()  ->default('draft')  ->default(Database::raw('CURRENT_TIMESTAMP'))  ->useCurrent()  ->useCurrentOnUpdate()
->unsigned()  ->unique()  ->index()  ->primary()  ->autoIncrement()
->comment('Homepage flag')  ->after('title')  ->first()  ->charset('utf8mb4')  ->collation('utf8mb4_bin')
->change()                                  // ALTER ... MODIFY (MySQL only)

Indexes and foreign keys

$table->primary(['a', 'b']);
$table->unique('email');   $table->unique(['post_id', 'tag_id']);
$table->index(['status', 'created_at'], 'posts_status_idx');   // optional custom name
$table->foreign('user_id')->references('id')->on('users')->cascadeOnDelete();
$table->foreignId('user_id')->constrained()->nullOnDelete();     // table guessed from the column: users
$table->foreignId('author_id')->constrained('users')->restrictOnDelete()->cascadeOnUpdate();

Index names default to table_col1_col2_type, which is what the drop methods compute when given columns.

Altering tables

Schema::table('posts', function (Blueprint $table) {
    $table->string('subtitle')->nullable()->after('title');
    $table->string('title', 200)->change();
    $table->renameColumn('views', 'hits');
    $table->dropColumn(['body', 'meta']);
    $table->dropIndex(['status', 'published_at']);   $table->dropUnique('posts_title_unique');
    $table->dropForeign(['user_id']);   $table->dropPrimary();   $table->dropSoftDeletes();   $table->dropTimestamps();
});

Schema::rename('posts', 'articles');   Schema::drop('old');   Schema::dropIfExists('old');   Schema::dropAllTables();

Inspecting the schema

Schema::hasTable('posts');   Schema::hasColumn('posts', 'slug');   Schema::hasColumns('posts', ['a', 'b']);
Schema::getTables();   Schema::getColumnListing('posts');
Schema::getColumns('posts');                 // [['name', 'type', 'nullable', 'default', 'auto_increment'], ...]
Schema::withoutForeignKeyConstraints(fn () => ...);
Schema::toSql($blueprint);                   // the DDL a blueprint would run

Every Schema method accepts a connection name as its last argument.

SQL migrations

A .sql file with -- up and -- down sections is also a migration. Statements are split on semicolons; keep the SQL simple (no semicolons inside string literals).

-- up
ALTER TABLE posts ADD COLUMN note VARCHAR(50) NULL;

-- down
ALTER TABLE posts DROP COLUMN note;

SQLite differences

The SQLite grammar covers creating tables (with inline foreign keys), adding, dropping and renaming columns, and indexes. SQLite cannot modify existing columns or add constraints to existing tables; those blueprints throw a clear RuntimeException. The MySQL-only modifiers after(), comment() and unsigned() are ignored on SQLite.

Seeders

php console.php make:seeder UserSeeder
php console.php db:seed                     # every file in database/seeders
php console.php db:seed --class=UserSeeder
<?php

return function (): void {
    User::factory()->count(10)->create();
    User::factory()->create(['email' => 'admin@example.com', 'name' => 'Admin']);
};

Factories

php console.php make:factory Post           # database/factories/PostFactory.php
<?php

class PostFactory extends Factory
{
    protected string $model = 'Post';

    public function definition(): array
    {
        return [
            'title' => fake()->unique()->sentence(4),
            'body' => fake()->paragraphs(3, true),
            'user_id' => User::factory(),                 // nested factory → created and reduced to its key
            'views' => fake()->number(0, 500),
            'published_at' => fn (array $attributes) => $attributes['views'] > 100 ? now() : null,
        ];
    }
}
Post::factory()->create();                                   // one saved model
Post::factory()->count(20)->create(['user_id' => $user]);    // Collection; models reduce to their key
Post::factory()->make();                                     // unsaved
Post::factory()->raw();                                      // attribute array only
Post::factory()->state(['published_at' => now()])->create();
Post::factory()->state(fn (array $attributes) => ['title' => strtoupper($attributes['title'])])->make();
Post::factory()->count(4)->sequence(['status' => 'draft'], ['status' => 'live'])->make();   // alternates
Post::factory()->afterCreating(fn (Post $post) => $post->tags()->attach(1))->create();

Fake data

Prefix a call with unique() to never repeat a value; fake()->seed(42) makes a run reproducible.
