Comparison with other frameworks

ComfreePHP, Laravel 13, Symfony 7.4 and plain PHP serving the same two endpoints from the same Apache, the same PHP 8.3 and the same OPcache, measured on 8 September 2026. Every number on this page comes from one script and one console command that you can run yourself.

The short version

  • JSON endpoints: ComfreePHP answers in 2.2 ms on a single client, Symfony in 4.1 ms and Laravel in 8.1 ms. Under 10 concurrent clients that is 1,850 requests per second against 1,010 for Symfony and 530 for Laravel, so ComfreePHP does about 1.8 times Symfony's throughput and 3.5 times Laravel's.
  • Full pages with a session and a CSRF token: ComfreePHP and Symfony are level (7.7 ms against 7.5 ms per request, 304 against 330 requests per second) while ComfreePHP renders a page three times larger; Laravel is behind at 11.3 ms and 209 requests per second, with a long tail of stalls from its session garbage collection.
  • Footprint: a ComfreePHP request loads 27 PHP files; Symfony loads 195 and Laravel 383.
  • Plain PHP is still faster than every framework, by a factor of two on pages and four on JSON. That gap is the price of routing, middleware, escaping, sessions and CSRF, and the point of this page is that ComfreePHP keeps it small.

What was measured

Two endpoints that every web framework has to serve, implemented as idiomatically as possible in each one:

Nothing touches a database. The full source of the other frameworks' routes and templates is in the benchmarks/ folder of the repository.

Environment

  • AMD Ryzen 7 5700G (8 cores, 16 threads), Windows 11 Enterprise, Windows Defender real-time protection on.
  • Apache 2.4.58 (mpm_winnt) with PHP 8.3.31 ZTS as a module, one Apache for all four applications, subdirectories with the frameworks' own .htaccess rewrite rules.
  • OPcache enabled with the XAMPP defaults: 128 MB, validate_timestamps=1, revalidate_freq=2, JIT buffer 0. All four applications fully cached (verified with opcache_get_status(), see below).
  • Laravel 13.30.1 (composer create-project laravel/laravel), Symfony 7.4.18 (symfony/skeleton plus twig, security-csrf and apache-pack), ComfreePHP at the commit this page ships with.
  • Load generated on the same machine, so the client competes with the server for CPU. That lowers every number equally and compresses the gap between the fastest targets; a separate client machine would widen it.

Reading the numbers honestly

  • This measures framework overhead, not applications. A real page spends most of its time in the database and the network, where all four are equal. The overhead matters when you serve many small requests, run on small hardware, or pay per CPU second.
  • Every page request writes a session file in all four applications, because every request from the load client is a new visitor. On Windows with real-time antivirus scanning that write costs several milliseconds and is the floor under the page numbers. ComfreePHP's JSON endpoint writes nothing because a request without a session cookie never starts a session; Laravel's is registered outside the session middleware and Symfony's sessions are lazy, so the JSON rows compare framework bootstrap and routing alone.
  • Laravel's long tail is its session garbage collector: the file session driver runs a full sweep of the session directory on 2% of requests, and every load-test request creates a new session file, so the 99th percentile grows with the length of the run. We emptied the session stores before each run; a real site sees this only under a burst of new visitors.
  • Laravel's page goes through its full web stack (cookie encryption, session, CSRF verification, view rendering), which is what a Laravel page does in production. Symfony's stateless CSRF tokens change length between responses, which makes ApacheBench report "failed" requests; bench:compare subtracts those, and the curl client never counted them.
  • Windows numbers are lower than Linux numbers for everyone: process-per-thread PHP, slower file I/O, antivirus scanning. Rankings on Linux are the same in our experience, with a larger absolute gap; run the script there to see your own.
  • Feature breadth is not measured. Laravel and Symfony ship far more (queues, mail, an ORM with migrations for every database, a huge package ecosystem). ComfreePHP covers the core a typical application uses and stays small on purpose; that is where its speed comes from.

The OPcache trap. Our first run had every framework losing: the XAMPP default OPcache (128 MB) was full from other projects on the same machine, so none of the four applications was actually cached and PHP recompiled hundreds of files on every request. Symfony, whose compiled container is one very large file, suffered most. Before you trust any PHP benchmark, check opcache_get_status()['cache_full'] is false and opcache_is_script_cached() returns true for the framework's core files, or raise opcache.memory_consumption and opcache.max_accelerated_files in php.ini.

Reproduce it

The benchmarks/ folder holds the routes, controllers and templates for Laravel and Symfony, the plain-PHP baseline, and a setup script that installs both frameworks with Composer, switches them to production mode and warms their caches:

bash benchmarks/setup.sh /var/www/bench        # or C:/xampp/htdocs/bench

php console.php bench:compare \
    comfree=http://localhost/app/ \
    laravel=http://localhost/bench/laravel/public/bench/page \
    symfony=http://localhost/bench/symfony/public/bench/page \
    raw=http://localhost/bench/raw/page.php \
    --requests=1000 --concurrency=10 --runs=3

php console.php bench:compare \
    comfree=http://localhost/app/api/ping \
    laravel=http://localhost/bench/laravel/public/bench/json \
    symfony=http://localhost/bench/symfony/public/bench/json \
    raw=http://localhost/bench/raw/json.php \
    --requests=1000 --concurrency=10 --runs=3

bench:compare warms every target, then hits them in alternating rounds so that background noise lands on all of them equally, and prints the median of the runs with 50th, 95th and 99th percentile latency, failures, response size and relative throughput. Add --concurrency=1 for pure latency, --ab to measure with ApacheBench instead of the built-in client, and --json for machine-readable output. Any set of name=url pairs works, so the same command compares two versions of your own application or two servers.

Footprint numbers come from /bench/info in the Laravel and Symfony applications and info.php in the plain-PHP baseline; add an equivalent route to your ComfreePHP application while measuring:

get('/bench/info', fn () => json([
    'included_files' => count(get_included_files()),
    'peak_memory_mb' => round(memory_get_peak_usage() / 1048576, 1),
]));

Publishing your own results? Include the hardware, the OS, the PHP and framework versions, the OPcache settings, whether the client ran on the same machine, and the exact commands. A number without those is not a benchmark.
