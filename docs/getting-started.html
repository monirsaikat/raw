Getting started

From a fresh checkout to a working page, a form and a database table in a few minutes.

Requirements

  • PHP 8.3 with pdo_mysql. The test suite also wants pdo_sqlite; if the extension is installed but disabled, the test command loads it on demand.
  • MySQL or MariaDB for the application database. SQLite works as well.
  • Apache with mod_rewrite, or the built-in PHP server for development.

Nothing is installed through Composer. Smarty lives in libs/ and Bootstrap in assets/vendor/.

Install

php install.php                  # asks for the app name and database, writes .env, generates the key
php console.php migrate          # creates the tables
php console.php serve            # http://127.0.0.1:8000

Or by hand: cp .env.example .env, then php console.php key:generate. To start a new application from this checkout, bash create-project.sh ../my-app copies the skeleton and runs the installer there (see Tooling).

Edit .env first: set APP_NAME, the DB_* values and, while developing, APP_DEBUG=true. Under XAMPP the project also runs straight from htdocs, for example at http://localhost/saikat/test1/; the .htaccess file routes every request through index.php and the base path is detected automatically.

Debug mode shows exception pages with code and stack traces and re-compiles templates whenever they change. Turn it off in production and run console view:clear after deploying template changes.

Your first page

Add a route in routes/web.php:

get('/hello/{name}', 'HelloController@show', 'hello');

Generate the controller with console make:controller Hello and edit controllers/HelloController.php:

<?php

class HelloController
{
    public function show(string $name)
    {
        return view('hello', ['name' => $name]);
    }
}

Create views/hello.tpl:

{extends file='layouts/main.tpl'}

{block name='title'}Hello — {$app_name}{/block}

{block name='content'}
    <section class="container my-5">
        <h1>Hello, {$name}!</h1>
        <a href="{navigate name='home'}">Back home</a>
    </section>
{/block}

Visit /hello/Ann. Output is HTML-escaped automatically, the layout provides the navigation, and {navigate} builds the URL from the route name.

A model, a table and a form

php console.php make:model Post -mf      # model + migration + factory

Edit the generated file in database/migrations/:

Schema::create('posts', function (Blueprint $table) {
    $table->id();
    $table->foreignId('user_id')->constrained()->cascadeOnDelete();
    $table->string('title');
    $table->text('body');
    $table->timestamps();
});

Run console migrate, declare the relationship and the fillable columns, then write the store action:

// models/Post.php
class Post extends Model
{
    protected static string $table = 'posts';
    protected static array $fillable = ['title', 'body'];

    public function author(): BelongsTo
    {
        return $this->belongsTo(User::class, 'user_id');
    }
}

// models/User.php
public function posts(): HasMany
{
    return $this->hasMany(Post::class);
}

// controllers/PostController.php
public function store()
{
    $data = validated(input(), [
        'title' => 'required|max:150',
        'body' => 'required',
    ]);

    auth_user()->posts()->create($data);
    flash('success', 'Post published.');

    return redirect_route('posts.index');
}

If validation fails the user is sent back to the form with $errors and $old available in the template. The route needs the auth middleware so auth_user() is never null:

group(['middleware' => ['auth']], function () {
    get('/posts', 'PostController@index', 'posts.index');
    post('/posts', 'PostController@store', 'posts.store');
});

Running the tests

php console.php test               # everything
php console.php test Router        # files whose name contains "Router"

Database tests run on an in-memory SQLite database and never touch your MySQL data. See Testing.
