CComfreePHP docs

Views

Templates are Smarty 5 files in views/. Output is escaped by default, layouts are inherited with blocks, and every template receives a few globals.

Rendering

return view('posts/show', ['post' => $post]);      // views/posts/show.tpl
view_exists('errors/404');                            // true when the file exists
View::share('menu', $menu);                            // available to every render for the rest of the request

view() returns the rendered string; the action returns it and the framework sends it. Data assigned to one render never leaks into the next.

Layouts and blocks

views/layouts/main.tpl holds the page chrome. Pages extend it and fill blocks:

{extends file='layouts/main.tpl'}

{block name='title'}Posts — {$app_name}{/block}

{block name='styles'}<link rel="stylesheet" href="{asset path='assets/css/posts.css'}">{/block}

{block name='content'}
    <section class="container my-5">
        {foreach $posts as $post}
            <h2><a href="{navigate name='posts.show' id=$post.id}">{$post.title}</a></h2>
            <p>{$post.excerpt}</p>
        {foreachelse}
            <p>No posts yet.</p>
        {/foreach}
        {$posts->links()|raw}
    </section>
{/block}

{block name='scripts'}<script nonce="{csp_nonce}">console.log('ready');</script>{/block}

The layout defines title, styles, content and scripts. Partials live in views/includes/ and are pulled in with {include file='includes/alerts.tpl'}.

Every render receives these variables in addition to what the controller passes:

$errorsValidation errors flashed by the previous request: $errors.email.0
$oldOld input flashed by the previous request: $old.email
$flashThe whole flash bag: $flash.success, $flash.error…

{if isset($errors.email)}<div class="invalid-feedback">{$errors.email.0}</div>{/if}

Escaping

{$var} is HTML-escaped automatically. Reading an undefined variable or key is silent (no notice), so {$old.name} is safe on a fresh form. For trusted markup use the raw modifier:

{$post.body_html|raw}
{$posts->links()|raw}

Only mark content as raw when you produced it or sanitised it yourself. Everything that came from a user must stay escaped.

Models and collections in templates

Models implement array access, so {$post.title} and {$post.author.name} work, including lazy-loaded relationships. Collections and paginators iterate with {foreach} and count with {count($items)}. Date attributes print as Y-m-d H:i:s and expose methods: {$post.created_at->diffForHumans()}.

Template functions and modifiers

TagOutput
{navigate name='user' id=$user.id}URL of a named route, extra attributes become parameters or the query string
{url path='about'}Base-path-aware URL
{asset path='assets/css/app.css'}Asset URL with a ?v= cache-busting version
{csrf_field}, {csrf_meta}Hidden token input; meta tag for JavaScript
{method_field method='DELETE'}Hidden _method input for PUT/PATCH/DELETE forms
{current_year}Four-digit year
{csp_nonce}The per-request nonce that the Content-Security-Policy allows for inline scripts
{if 'home'|route_is}True when the current route matches (wildcards allowed: 'admin.*')
{if 'update'|can:$post}, {if 'delete'|cannot:$post}Authorization checks for the logged-in user

Register more in config/view.php: a functions entry maps a tag name to a PHP function receiving the attribute array; a modifiers entry maps a modifier to a function receiving the value and any arguments.

Forms

<form method="post" action="{navigate name='posts.update' id=$post.id}">
    {csrf_field}
    {method_field method='PUT'}
    <input name="title" value="{$old.title|default:$post.title}">
    <button type="submit">Save</button>
</form>

Flash messages

The layout includes views/includes/alerts.tpl, which shows $flash.success, $flash.error, $flash.warning and $flash.info as Bootstrap alerts. Set one with flash('success', 'Saved.') before redirecting.

Error pages

views/errors/error.tpl renders every error status with $status, $title and $message. Add views/errors/404.tpl (or any status) to customise one. Error templates are standalone by design so they still render when the layout's dependencies are unavailable.

Compilation

Smarty compiles templates into storage/views. With APP_DEBUG=true it re-compiles when a .tpl changes; otherwise it skips the check for speed, so run console view:clear after deploying template changes. Paths and options are in config/view.php.
