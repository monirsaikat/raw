Localization

Strings live in lang/, one directory per locale. __() reads them, trans_choice() pluralises, and the locale middleware picks the language per request. Untranslated keys fall back to the fallback locale, then to the key itself, so an app can start in one language and add others later.

Files

lang/
  en/
    auth.php          'failed' => 'Those credentials do not match our records.'
    messages.php      'welcome' => 'Welcome to :app'
    pagination.php    'previous' => 'Previous', 'next' => 'Next'
    validation.php    'required' => 'The :field field is required.', 'custom' => [...], 'attributes' => [...]
  bn/
    ...               same files, translated values
  bn.json             {"Save changes": "পরিবর্তন সংরক্ষণ করুন"}

PHP files return arrays and are addressed by group.key (messages.welcome); nested arrays use more dots (validation.custom.email.required). A <locale>.json file holds flat sentence keys for apps that prefer __('Save changes') to invented identifiers. Both may be used together.

Reading strings

__('messages.welcome', ['app' => app_name()]);      // "Welcome to Shop"
__('Hello :name', ['name' => 'ann']);               // JSON key, or the key itself when missing
__('Hello :Name / :NAME', ['name' => 'ann']);       // "Hello Ann / ANN" — placeholder case is applied
__('auth.failed', [], 'bn');                        // explicit locale
trans('auth.failed');                               // alias of __()
lang_has('messages.welcome');                       // bool

trans_choice('messages.items', 0);                  // '{0} No items|{1} One item|[2,*] :count items' → "No items"
trans_choice('messages.items', 7);                  // "7 items"
trans_choice('shop.apples', $count);                // 'apple|apples' → singular for 1, plural otherwise
trans_choice('messages.items', $collection);        // countables use their count

Plural lines are pipe-separated. Two plain segments mean singular and plural. Explicit forms use {n} for one number and [a,b] for a range (* is open-ended). :count is filled in automatically.

Choosing the locale

app_locale();                       // current locale, "en" by default (config('app.locale'))
set_locale('bn');                   // for the rest of the request
set_locale('bn', remember: true);   // and store it in the session
locale_is('bn', 'hi');              // bool
lang_available();                   // ['bn', 'en'] — what exists in lang/
fallback_locale();                  // config('app.fallback_locale')

The locale middleware runs on every route (it is in the global middleware list). It picks, in order: a ?lang= query parameter, which is also stored in the session; the locale stored in the session; the best match from the Accept-Language header (fr-CH matches fr); and finally config('app.locale'). Only locales present in lang/ are ever chosen, so the parameter is safe to expose as a link:

{foreach lang_available() as $locale}
    <a href="?lang={$locale}"{if $locale == $app_locale} class="active"{/if}>{$locale}</a>
{/foreach}

Use a different parameter name with global_middleware(['csrf', 'locale:language']), or drop locale from the list and call set_locale() yourself, for example from the logged-in user's profile in your own middleware.

Validation messages

lang/<locale>/validation.php overrides the built-in rule messages. Precedence, highest first: messages passed to validated() / validate(), custom.<field>.<rule> in the lang file, <rule> in the lang file, the same keys in the fallback locale, the rule's default text. attributes renames a field in every message (:field and :attribute are interchangeable):

return [
    'required' => 'Please fill in :attribute.',
    'custom' => [
        'email' => ['required' => 'We need your email address.'],
    ],
    'attributes' => [
        'email' => 'email address',
        'dob' => 'date of birth',
    ],
];

Adding a locale

php console.php make:lang bn            # copies lang/en/*.php (and en.json) to bn
php console.php lang:missing bn         # keys en has that bn lacks, or that are still identical to en
php console.php lang:list               # locales and key counts

Translate the values and keep the keys. lang:missing exits non-zero when keys are missing, so it can run in CI.

Runtime lines and tests

lang_add('en', 'shop', ['total' => 'Total: :amount']);   // packages, tests
lang_reset();                                              // forget loaded files and the chosen locale
config_set('app.lang_path', $directory);                   // read lines from somewhere else

The test runner resets the locale and the loaded lines between tests. Pass a header to exercise detection: http_get('/', ['Accept-Language' => 'bn']).
