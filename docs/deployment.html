Deployment

Copy the files, set the environment, run the migrations, warm the caches. There is no build step and nothing to install.

Checklist

  1. Upload the project (excluding .env, storage/ contents, bootstrap/cache/, tests/ and docs/ if you like).
  2. Create .env with APP_ENV=production, APP_DEBUG=false, the database credentials and a generated APP_KEY.
  3. Make storage/ (logs, cache, views) writable by the web server; everything else can be read-only.
  4. php console.php migrate
  5. php console.php route:cache and php console.php view:clear
  6. Serve over HTTPS; then set HSTS_ENABLED=true.

Apache

Point the document root at the project directory, or place the project in a sub-directory of an existing root; both work without configuration because the base path is detected. mod_rewrite must be enabled and AllowOverride All set for the directory so .htaccess is honoured.

<VirtualHost *:443>
    ServerName example.com
    DocumentRoot /var/www/app
    <Directory /var/www/app>
        AllowOverride All
        Require all granted
    </Directory>
</VirtualHost>

The shipped .htaccess routes non-file requests to index.php, blocks dotfiles, disables directory listings, and, when the modules are present, compresses text responses (mod_deflate) and sends year-long cache headers for versioned assets (mod_expires, mod_headers). Those blocks are wrapped in IfModule, so a server without them still works. Sensitive directories carry their own deny rules; verify with a request to /.env or /core/route.php, which must return 403.

Other servers

Nginx or Caddy need the equivalent of the rewrite rule (try the file, else index.php) and must deny access to every directory except assets/ and, if published, docs/. The built-in server (console serve) is for development only.

PHP settings

  • opcache.enable=1; on immutable deployments also opcache.validate_timestamps=0 and restart PHP after each deploy.
  • display_errors=Off (the framework renders errors itself), log_errors=On.
  • upload_max_filesize and post_max_size according to your forms.
  • Sessions use PHP's default file handler; on a multi-server setup point session.save_path at shared storage or a session extension.

Database

Run migrate on every deploy; it is idempotent. Keep backups before migrate:rollback or migrate:fresh in production; the latter drops every table. Use DB_SLOW_QUERY_MS to spot slow queries in the log.

Health

GET /api/ping returns JSON with the current time and the logged-in user (null for monitors), which makes a cheap liveness check. Add a route that touches the database if you need a readiness check.

Upgrading PHP

The code targets PHP 8.3 and uses no extensions beyond PDO, mbstring, intl (for slugs, optional), json and the standard library, so newer PHP versions should need no changes beyond running the test suite.
