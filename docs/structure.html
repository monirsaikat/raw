Structure and lifecycle

Where files live, what bootstrap loads, and what happens between a request arriving and a response leaving.

Directory layout

PathPurpose
index.php, console.phpWeb and CLI entry points. Both load core/bootstrap.php.
core/The framework. Lower-case files define functions (route.php, http.php, auth.php…); capitalised files are classes (Model, QueryBuilder, Schema, Container…). Application code never needs to edit this directory.
config/Plain PHP arrays read with config('app.name'). Values come from .env through env().
routes/web.phpRoute definitions.
controllers/, models/, services/, policies/Autoloaded application classes, one class per file, file name equal to the class name.
middleware/Application middleware, one file per handler, loaded automatically.
views/Smarty templates: layouts/, includes/, errors/, and pages.
database/migrations/, seeders/, factories/.
helpers/helpers.phpGeneral-purpose helpers for application code (view(), asset(), collect(), fake()…).
assets/Public CSS, JavaScript and images. Served directly by Apache, versioned by asset().
storage/Logs, cache files, compiled templates, SQLite files. Git-ignored and web-blocked; must be writable.
bootstrap/cache/The compiled route table from console route:cache.
tests/Test files run by console test.
libs/Vendored third-party code (Smarty).
docs/This documentation.

Every directory that must not be reachable from the browser carries a .htaccess that denies access. The root .htaccess also blocks dotfiles such as .env.

Bootstrap

core/bootstrap.php runs once per process, in this order:

  1. Defines BASE_PATH and APP_START.
  2. Loads .env and the config reader, defines APP_DEBUG, sets the timezone.
  3. Registers the autoloader for core/, controllers/, models/, services/ and policies/.
  4. Installs the error handlers: warnings become exceptions, uncaught exceptions are rendered.
  5. Loads the core modules (container, HTTP helpers, session, flash, cache, middleware, routing, security headers, CSRF, validation, auth, authorization, throttling) and helpers/helpers.php.
  6. Registers the container bindings from config/container.php and the authorization gate.
  7. Includes every file in middleware/.

Including bootstrap a second time is a no-op, so tests and scripts can require it freely.

Request lifecycle

  1. Apache rewrites the URL to index.php unless it names a real file (assets are served directly). The built-in server does the same through a check at the top of index.php.
  2. index.php loads bootstrap, then the route table: the compiled cache when APP_DEBUG is off and the cache exists, otherwise routes/web.php.
  3. route() starts output buffering, sends the security headers, and calls route_dispatch() with the request method (honouring _method spoofing) and the path relative to the base path.
  4. route_dispatch() finds the route: an O(1) lookup for static paths, then the pre-compiled regexes for dynamic ones. No match gives a 404, or a 405 with an Allow header when the path exists for other methods.
  5. The global middleware (csrf) and the route's middleware run as an onion around the action.
  6. The action is built and called through the container: constructor dependencies are injected, route parameters are mapped by position, parameters typed with a model class are loaded by key.
  7. The return value is sent: a Response as is, an array or model or collection as JSON, a string as HTML.
  8. Anything thrown reaches handle_exception(), which logs 5xx errors and renders the debug page, a JSON payload or views/errors/error.tpl. A ValidationException becomes a redirect back with the errors and old input flashed.

Sessions start lazily

No session is opened until the first session_*(), flash(), csrf_token() or auth_*() call. A JSON endpoint that touches none of them costs no session lock. Rendering a view starts one, because the layout reads the logged-in user and the CSRF token.

Coding conventions

  • Helpers are snake_case functions; classes use PascalCase and live in files named after them.
  • Controllers are plain classes with public methods; they return values rather than echoing.
  • Everything that reaches the browser goes through send_response(); do not call header() or exit yourself.
  • Request data is read with input(), never $_REQUEST (which would include cookies).
