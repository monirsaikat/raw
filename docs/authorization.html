Authorization

Who may do what. Model abilities live in policies, everything else in gates; both are checked with the same helpers in controllers, templates and routes.

Policies

php console.php make:policy Post           # policies/PostPolicy.php
<?php

class PostPolicy
{
    // Optional. Runs first for every ability; true/false decides, null continues.
    public function before(User $user, string $ability): ?bool
    {
        return $user->is_admin ? true : null;
    }

    public function viewAny(User $user): bool          { return true; }
    public function view(?User $user, Post $post): bool { return $post->published || $user?->id === $post->user_id; }
    public function create(User $user): bool           { return true; }
    public function update(User $user, Post $post): bool { return $post->user_id === $user->id; }
    public function delete(User $user, Post $post): bool { return $post->user_id === $user->id; }
}

A policy is found by name: PostPolicy for Post. Other pairings go in config/auth.php under policies, or gate_policy(Post::class, ArticlePolicy::class). Policies are built by the container, so their constructors may declare dependencies. The ability name maps to a method; update-title becomes updateTitle().

Gates

Standalone abilities live in policies/gates.php:

gate_define('admin', fn (User $user) => (bool) $user->is_admin);
gate_define('view-dashboard', fn (?User $user) => $user !== null);
gate_define('export', 'ExportRules@allowed');                        // Class@method, built by the container

gate_before(fn (?User $user) => $user?->is_superuser ? true : null); // runs before everything
gate_after(fn (?User $user, string $ability, ?bool $result) => ...);  // decides only when nothing else did

Checking

can('update', $post);   cannot('update', $post);   can_any(['update', 'delete'], $post);
can('create', Post::class);                                   // class-level abilities
can('admin');

authorize('update', $post);                                   // throws AuthorizationException → 403
abort_unless(can('update', $post), 403);                      // same thing, by hand

$user->can('update', $post);   $user->cannot(...);   $user->canAny([...], $post);   // Authorizable trait
gate()->forUser($other)->allows('update', $post);             // as another user
gate()->forUser(null)->allows('view', $post);                 // as a guest
{if 'update'|can:$post}<a href="{navigate name='posts.edit' id=$post.id}">Edit</a>{/if}
{if 'delete'|cannot:$post}<span class="text-muted">Locked</span>{/if}
{if 'admin'|can}...{/if}

Route middleware

get('/admin', 'AdminController@index', 'admin', ['auth', 'can:admin']);
get('/posts/{id}/edit', 'PostController@edit', 'posts.edit', ['auth', 'can:update,Post@id']);   // model from the route parameter
get('/posts/create', 'PostController@create', 'posts.create', ['auth', 'can:create,Post']);     // class name
get('/reports/{year}', 'ReportController@show', null, ['can:view-report,year']);               // raw parameter value

Arguments after the ability: Model@param loads the record (404 when missing), a class name is passed as is, anything else is the named route parameter's value. Put auth before can so guests are sent to log in rather than receiving a 403.

How a check is resolved

  1. Each gate_before() callback runs; a non-null result is final.
  2. If the first argument is a model instance or class with a policy: the policy's before() (if any), then the method named after the ability. A missing method denies.
  3. Otherwise the gate definition with that name; no definition denies.
  4. gate_after() callbacks may decide when the result is still null.

Guests: a callback or policy method is only invoked for a guest when its first parameter is nullable (?User $user) or has no type. Otherwise the ability is denied without calling it, so policies never receive null by surprise.

Handling denial

AuthorizationException is an HttpException with status 403. The error handler renders views/errors/403.tpl if it exists, else the generic error page, or a JSON {"message": "This action is unauthorized."} for JSON clients.

Testing

test('only the author can edit', function () {
    $post = Post::factory()->create();

    assert_true($post->author->can('update', $post));
    assert_false(User::factory()->create()->can('update', $post));

    acting_as(User::factory()->create());
    http_get('/posts/' . $post->id . '/edit')->assertForbidden();
});
